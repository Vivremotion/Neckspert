# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A fretboard-memory trainer for guitarists, built as a rhythm game. The player hears a metronome, sees a prompt ("F, corde de B"), and plays the note on a real guitar on the beat (mode 1, _locate_), or taps the note name for a given string/fret (mode 2, _identify_). Spaced repetition (FSRS via `ts-fsrs`) decides what comes back; only the first, _cold_ attempt at a card after a delay feeds retention stats. Read `PRODUCT.md` for the product rules and `docs/brief.md` for the original brief. Product docs, plans and UI copy are in French; code, identifiers and comments are in English.

## Commands

Node 22.23.3 (`.nvmrc`, `engine-strict=true`). Scripts are in `package.json`; `npm run check` is `svelte-kit sync` + `svelte-check`.

Vitest has two projects (`vite.config.ts`): `*.spec.ts` runs in **node** (`server`), `*.svelte.spec.ts` runs in **jsdom** (`client`, `npx vitest run --project client`). Any test that renders components or uses runes must be named `*.svelte.spec.ts`. `expect.requireAssertions` is on, so every test must assert. Dexie specs import `fake-indexeddb/auto`. The merge gate used throughout the plans is `npm test && npm run check`.

`scripts/functional-ui.mjs` drives real pages in headless Chrome against running dev servers (it fails on behavior errors and on text under 16px). It is not part of `npm test`.

## Architecture

Svelte 5, runes only (forced for all non-`node_modules` files), SvelteKit with `ssr = false`, no component library, native CSS with variables. Layered, ports-and-adapters:

- `src/lib/domain/` — pure logic, no Svelte, no browser APIs. `types.ts` holds the shared domain model (cards keyed by `cardKey(mechanic, itemKey)`).
- `src/lib/application/` — `ports/` defines the interfaces infrastructure must implement. `app.ts` defines `AppServices`, the single object screens consume, provided through Svelte context (`provideAppServices` / `useAppServices`). `session/contract.ts` defines `PlaySessionController` and its reactive `PlayView` — the contract between orchestration and the play screen.
- `src/lib/infrastructure/` — adapters. One `WebAudioClock` owns the single `AudioContext`; one raw `WebAudioInput` is shared and its frames feed every detector. A played note is an attack of the attack sensor and the pitch read after it. Diagnostic journal and audio-input rules: `src/lib/infrastructure/CLAUDE.md`.
- `src/lib/composition/createApp.ts` — the composition root: wires real adapters into `createAppServices`. Called once in `src/routes/+layout.svelte`.
- `src/lib/ui/` — `notation/` is the only VexFlow importer, loaded lazily; `notationReady()` awaits the embedded Bravura font before engraving. Visual system: `src/lib/ui/CLAUDE.md`. Each screen has a `messages.ts` using `defineMessages({ fr, en })` from `$lib/i18n/index.svelte`; locale comes from stored settings.
- `src/routes/` — thin pages that pull `useAppServices()` and render a screen. `/dev/*` (screens with fake services) and `/diagnostic` are gated by `requireDev()` and 404 in production.

Tests use fakes from `src/lib/testing/fakes.ts`. Repository behavior is specified by reusable contract suites in `src/lib/infrastructure/storage/testing/`, which the Dexie repository specs run.

## Rules that span files

These are fixed product decisions documented in `docs/superpowers/plans/README.md` (read it before changing scoring, timing or audio behavior). All numbers are named constants meant to be tuned, not inlined.

- **Times**: audio scheduling uses `AudioContext` seconds; scoring windows and reaction times are in ms; musical positions and durations are exact fractions of a whole note (`domain/time/`). Onsets are corrected by the calibrated latency of their sensor before judging: `Settings.latency` holds one `SensorLatency` per sensor (`note`, `chord`, `attack`…) with its provenance (`'system'`: measured without the player's gesture; `'player'`: from the player's attacks on the click). The calibration (`audio/calibration/CalibrationService`) measures it without the player: the computer's mic, a second `WebAudioInput` in the same context opened `raw`, is calibrated on clicks heard in silence (`loopLatency`: only clicks heard at one common delay count, with a minimum share and a spread limit), then the interface is compared with it on notes played freely (`pairedDelay`: constant offset found wide, then one-to-one pairs, a minimum of pairs and a spread limit); with the built-in mic alone, the click loop is the latency and a separate bleed check follows, headphones back on; `note` = `chord` = `attack` + the note detector's own delay, anchored on the notes; the reference mic's tracker is more sensitive (`REFERENCE_ATTACK_CONFIG`). It never falls back by itself: a failed reference ends with `reason: 'reference'` and its numbers, and the calibration on the click (`runOnClick`, `player` for all, notes within `PLAY_MAX_OFFSET_MS` of a click) is the player's explicit second choice; the screen shows the measure (`CalibrationMeasure`). `run(deviceId, onProgress)`; the page writes the device, `latency` and `clickBleed` together, only on success. A sensor without a latency of its own takes its fallback's, as provenance `player` (`sensorLatency`, `session/latency.ts`; `LATENCY_FALLBACK`: `attack` → `note`). `Settings.clickBleed` (click heard on the playing input) makes the start screen ask for headphones when the rounds listen with a sensor the click would fool (`asksForHeadphones`, `session/clickBleed.ts`: the `attack` sensor; `PlayView.audioError: 'bleed'`), the first how-to still shown below; the series is not refused.
- **Metronome** (the click is one of the transport's sounds; there is no metronome port since H5, see « Musical time »): a session's first start waits for `clock.settle()` (a fresh audio output loses its first sounds: `WebAudioClock` waits until it has played `OUTPUT_WARMUP_S`, so the counted bar's downbeat is heard); the transport starts at `clock.now() + START_DELAY_S` (0.1) at the earliest; a sound whose time is past is dropped, not played late. `Transport.at(bar, callback)` (over `SoundSchedulerPort.at(time, callback)`) wakes the session once the audio clock reaches that time, at the scheduler's next wake-up (never early, at most `DEFAULT_LOOKAHEAD_MS` late); the returned function or `cancelAll` cancels it. The tempo changes only over bars not yet scheduled (`changeTempo` and `changeMeter` throw otherwise). `FakeSoundScheduler.flush()` runs the wake-ups due, earliest first. The clock's `epochNow()` is the wall time before the audio context exists, so a cold load of `/session` shows its start screen (the context is created by Start).
- **Bar grid** (mode 1): by default the target lands on beat 1 of a bar; a plan may say where its round starts in the bar (`RoundPlan.barOffset`, written by an exercise in its `round` template) and where its count ends (`countEndsOn`: `'prompt'` by default, `'target'` for a grid change; written by an exercise in its `round` template); a round is never placed with its prompt already past (`comingStart`, a bar later while it would be). Leads come from the exercise's ladder (locate 8, 4, 2: prompts on beat 1 or 3); a lead, like a beat-valued window, may be any exact fraction of a beat (`beatsOf`/`isBeatCount` in `domain/time/meter.ts`, over `Fraction.fromNumber`, shared by the round compiler and the validation). Where the next round goes is decided in one pure function (`placeNext`, `series/placement.ts`: chained, after the breath, at the next beat, or after a counted bar). One rule places every timed round without a handover (`timedStart`): the first start ≥ `earliest` (end of the counted bar, or of the previous round, whose plan ends with its exercise's breath, `params.pacing.respirationBars`, default `DEFAULT_RESPIRATION_BARS`) that lies `barOffset` into its bar and, when the count ends on the prompt, whose prompt is not before `earliest`; a free-time round (identify) opens at the next beat (`nextBeat`) and settles at its answer, the tempo map running on. In the breath a miss shows the right answer (`VerdictView.correction`); the next item shows its `previewBeats` before its prompt (the exercise's `flow.previewBeats`, else the presenter's, resolved once by `previewBeatsOf` and read by the template as `{ param: 'previewBeats' }`, 0 without one: `DEFAULT_PREVIEW_BEATS` for locate, the string alone), the settled round staying until then. The triads place by the same rule (the anchor: its root on the target, its chord's band to the end of the bar). A change of scene is a counted bar (`PlannedItem.countIn`), and so is a change of meter: the series plays each item in its exercise's meter and moves to another with `Transport.changeMeter` (positions go on, the part of a bar before the new meter's first whole bar stays silent), chaining only within one meter. A `countIn` item may ask `restBars` of silence before its counted bar (the click muted, given back on the beat before the count or on pause); the link asks it at each new chord or set.
- **First note is the answer**; later notes are ignored. The windows are exercise data (`params.windows` over `DEFAULT_RESPONSE_WINDOWS`, read by the template as `{ param: 'windows.…' }`). The window opens `minResponseMs` after the prompt: earlier notes belong to the previous prompt and never answer this one. Mode 1 verdicts: wrong pitch/no answer → `wrong`, `|offset| ≤ perfectMs` → `perfect`, else `early`/`late`. Past `lateMs` the round keeps listening for `lateCaptureMs`, bounded by where the next expectation is due and by the end of listening (`listenUntil`: the next prompt's string preview for locate, the round's end for the triads; `responseZones`, `domain/time/modes/firstAnswerTimes.ts`): a right note there is `offbeat` (correct, graded Hard, never direct recall — `isDirectRecall` of the `response` verdict checks it; it counts as a miss for its level), a wrong one stays `wrong`; an attack goes to the earliest unanswered expectation whose zone holds it. The attempt is stored once the capture settles. Order: perfect > early/late > offbeat > corrected > wrong (`corrected`: a triad anchor's wrong first chord put right later in the band; `correct: false`, a miss everywhere, only the screen salutes it). This one-answer verdict is `ResponseVerdict`. Every attempt stores `success` (the relation's word on whether the round passed), `correct: boolean | null` (the judge's word on the content; null when nothing was judged, as in a rhythm cycle; a cycle with content is correct when no expectation is `wrong-pitch` or `missed`), `verdict` as an envelope `{ relation, version, value }` (`responseVerdictOf` reads it back for the response relations `RESPONSE_RELATIONS`), `measures`, `aids: Aid[]` and the resolved `plan` (`RoundPlanRecord`, `series/recordResponse.ts`: the plan in JSON, its `startAudioS`, its `tempo`, the `thresholds` its verdict read; `roundPlanFromRecord` reads it back). Every settled round is written one way (`roundAttempt` over `recordedAttempt`; a round judged by the cycle verdict keeps `FigureAttemptData`: item, level, report). `Attempt.success` is what stats, grades and pacing read, never `correct` (`domain/successBoundary.spec.ts`); for a response round the `response` verdict mode decides it (correct and not offbeat, `domain/time/modes/responseVerdict.ts`), and direct recall reads it (`directRecallOf`, the subject's `recall`). Mode 2 has no `early` and no `offbeat`.
- **Cold vs hot**: only cold attempts feed retention, FSRS and mastery. A free-play attempt on a learned card untouched for `MIN_COLD_DELAY_MS` is cold too. Deliberate exception: a probe is cold only when passed; a missed probe is stored hot because it measures no forgetting (`probeTemperature`, the only place that decides it).
- **Sessions** are `'learn' | 'free'` for the notes, `'triads' | 'triads-zone'` for the triads (one exercise per session, the learning procedure with `triadSubject({ mechanic, … })`; the zone shows on the home screen once `triadZoneOpen`, `domain/triads/zoneOpen.ts`, and a zone session with nothing to ask ends on the summary). The notes and the triads play on `SessionController` for the `durationMs` their preparation returns (`SESSION_MS` for every session, written in `createAppServices`; no round that does not continue a handover starts after it), each item a round compiled from its exercise's `round` template (`compileRound`, `domain/exercise/round/`) at its level's lead. Free play runs a fixed list (`createListSource`, locate's lead from the card's `LevelState` on the locate ladder, `freeLeadOf`); learn runs the learning procedure (`createLearningProcedure` with `neckSubject`): retests, cold reviews, resumed notes, new notes, then consolidation. A new note is first served as an unaided `'probe'`: a direct recall makes it a review card (`probeCard`), a miss brings the aided presentation on the next prompt. Inside a category the draw is random (injected `random`, `progress/order.ts`): never the previous card, never its mirror (`music/mirror.ts`), another string when possible; a note waits in the queue while its mirror is not acquired. New notes also need `NEW_NOTE_MIN_CARD_SUCCESS` on every note being learned and `NEW_NOTE_MIN_SESSION_SUCCESS` over the last `SUCCESS_WINDOW` mode 1 prompts (`progress/success.ts`); a miss (probes left out) brings a solid card next as hot `'consolidation'` (recovery); hot prompts stay within `MAX_WORKING_SET` cards (these constants are the defaults of the set's settings, see below). The tempo is per exercise, not a setting (`settings.tempoBpm` is gone, nor is it in the Settings screen): an exercise writes `tempo` (a number, beats of its meter per minute; absent: `DEFAULT_TEMPO_BPM`, 80), which its exercise levels may override like any parameter (`tempoOf(definition, exerciseLevel)`; see « Mechanics and exercises »); locate, identify and the triads write no levels and play at 80 bpm. An exercise level is held per (exercise, scope) in a `LevelState` (item `''`, stored only for an exercise that writes levels), read once per series and moved by every settled round (`ExerciseLevels`, `series/exerciseLevels.ts`, over `nextLevelState`); a level reached applies at the next round that does not chain (after a breath or before a counted bar), announced (`PlayView.announcement`), with a counted bar at its tempo; a chained round keeps the level of its run, and the next session starts at the level reached. A scope is generic and optional (`PlannedItem.scope`, stored as `Attempt.scope`); another exercise's or scope's tempo brings a counted bar at its tempo; the session record keeps one `Execution` per (exercise, scope) met, at the tempo of its first round (null in free time). The gesture scopes its grid exercises by grid (a ballad and a blues progress apart); the link has one level. Specs: `docs/superpowers/specs/2026-10-02-apprentissage-design.md`, `docs/superpowers/specs/2026-10-03-sondage-avant-apprentissage-design.md`, `docs/superpowers/specs/2026-10-04-rythme-et-consigne-design.md`. One learning procedure (`domain/learning/`, `createLearningProcedure`) is driven by a `LearningSubject` per exercise (`neckSubject`, `triadSubject`) and keeps one `LevelState` per item on the ladder its exercise writes (`params.ladder` or `params.ladders[mechanic]`, read by `ladderOf`: levels of `LadderParams`, lead, aided, pass and drop, the top marked `success: 'direct-recall'` where only a direct recall counts), moved by `nextLevelState`; an item's settings (`retestGaps`, `aidFadeSuccesses`) come from its exercise's `params.learning` (`itemLearningOf`), the set's (slots, working set, introduction thresholds, consolidation, category `order`, `recoveryAfterMisses`…) from the session, `createLearningProcedure({ set })`, today `DEFAULT_SET_LEARNING`; the direct-recall threshold is exercise data (`params.recallThresholdMs`, read by `recallThresholdOf`), `ItemSource` names every item source and `choose` picks a series among candidates. A level held above the ladder's top (`ladderLevel`) is served at the top, and every attempt writes the level played. The triads' rules (a new chord probed unaided, aided on the next prompt after a miss, never the same voicing twice, the zone asking only chords acquired in the anchor and another shape than the last) are played end to end in `series/triadsSession.spec.ts`.
- **Gesture track** (spec `docs/superpowers/specs/2026-10-10-voie-geste-design.md`): session kind `'gesture'` (`createGestureSelector`, `progress/gestureSelector.ts`), one mechanic `chord-grid` (`domain/mechanics/chordGrid.ts`, `learner: 'skill'`: attempts kept with their observations, no card) for four exercises in the order of the ladder, `gesture-link`, `gesture-climb`, `gesture-zone`, `gesture-jam` (`domain/gesture/`: elements, `linkShapes`, `nextZone`, opening from the triad cards acquired, `passageSucceeded` at `PASSAGE_SUCCESS`, `summarizeGesture`). Grids are data written with real symbols (`domain/grid/`: `iohefy-a`, `blues-f`; `parseChordSymbol` over the `SUFFIXES` table, `triadOf` over `TRIAD_OF_QUALITY`, `gridChanges` merges equal symbols in a row); `QUALITIES` holds triads and sevenths, triad code keeps `isTriadQuality`. A passage is a grid played once; each change is an attempt (`ChordGridItem`, key `${element}#${index}`). Rounds of a passage hand over without a gap, at the next change minus `min(windows.gridEarlyMs, windows.gridEarlyMaxBeats` beat`)`: the series controller wakes there (`transport.at`), withdraws the expectations, closes the round (`RoundRunner.close`), and opens the next change at once (chained) unless it has `countIn`, another tempo or another scene; pause, quit and finish cancel the wake-up. Its four exercises write their `round` (content `grid-change`, length `{ item: 'change-beats' }`, `handover: 'end'`, `countEndsOn: 'target'`) but no `presentation`: their screen models stay their presenter's (`stageOf`) until the gesture becomes data (D9 of H5). In a climb, at a change where no shape of the chord on the set lies strictly beyond the last shape heard, the direction turns there and for the rest of the passage (`climbDirection`, computed by the selector and carried on the items, so the judge stays pure; the aid follows it); passages alternate by their starting direction. Zones span `ZONE_FRETS` frets; an open string counts inside the zone at fret 1 only; the rotation visits every start from 1 to `MAX_VOICING_FRET − ZONE_FRETS + 1`, `ZONE_STEP_FRETS` (5) apart modulo the starts, skipping a zone where a chord of the grid has no shape (`nextZone`, `domain/gesture/passages.ts`). What the implementation decided against the spec is listed in its section « Réalisation ». Its four exercises write `tempo: 80` and nine exercise levels, ♩ = 80 to 120 by 5, each passed after 10 changes right in a row unaided and left after 3 missed in a row (`tempoLevels`, `domain/gesture/exercises.ts`; the gesture's data, not an engine rule): the level moves at every settled change, the tempo at the next passage, after its counted bar (a link tour played again, `continued`, keeps it). The home screen offers « Geste » once `AppServices.gesture().open`; the summary sums a gesture session up by exercise and grid (`SessionSummary.gesture`: the first and the last tempo played, `lastTempoBpm`) with « Joué juste » on its misses (`AppServices.contest`). Setting the constant to false removes it; nothing else depends on it. Confusions include `'string-name'`: the open note of the prompted string played instead of the target.
- **Open strings** (fret 0) are never prompted: the prompt names the string by its open note.
- **Chord sensor** (spec `docs/superpowers/specs/2026-10-07-capteur-accords-design.md`): a mechanic gives its sensor an expectation per round (`MechanicPresenter.expectation?` → `ObservationSource.expect?`, opaque to the core); `chordSensor` turns reports into observations. Expectations are withdrawn (`expect(null)`) before a span closes, so a window cut short reports into its own round. The ringing previous chord is never a candidate. The verifier judges each attack from `FIRST_READING_MS` every `JUDGE_EVERY_MS` until a reading is final (expected shape, the same shape `STABLE_READINGS` times, nothing at `NOTHING_FINAL_MS`, or the last one), then stops; a new attack closes an earlier window only once it is older than `ARPEGGIO_SPAN_MS`, so an arpeggio stays whole and a chord played again later is read apart (known risk: a chord played again within that span is read with the first). In the anchor the first chord is the answer: a wrong one shows at once as a provisional miss (`PlanRound.observe` may return `provisional`), and a later right attack in the band settles `corrected` (spec `docs/superpowers/specs/2026-10-09-retours-voie-memoire-design.md`). After a miss, the lane draws what was heard and expected with `ChordShape` and tells the gap and the right shape (`CONTENT_VIEWS['chord-voicing'].miss` → `StageVerdict.misses`, drawn through `PICTURE_VIEWS`; a missed root tells its position), the gesture's views likewise through their presenter's `feedback`, in the style of `Settings.chordDiagram` unless the exercise imposes `ExerciseDefinition.chordDiagram`; a contestable mechanic's miss can be contested in play (« Joué juste », Enter; `PlayView.contest`, `contest()`), until the next prompt. Known risk: D 2-3-2 right after a ringing 7-7-5 is falsely taken for 11-10-10 (frozen fixture).

## Workflow conventions

- Implementation plans and specs live in `docs/superpowers/plans/` and `docs/superpowers/specs/` (dated, in French). Plan work historically ran in git worktrees under `.worktrees/` on `plan/<id>` branches.
